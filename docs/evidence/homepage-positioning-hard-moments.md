# Homepage Positioning: Hard-to-Write Moments

Date: 2026-03-14

## Scope

- Reviewed homepage positioning in `public/index.html`
- Reviewed hero experiment/default copy in `public/js/experiments.js`
- Reviewed generated LLM/discovery description source in `scripts/generate-llms.js`
- Reviewed repo-visible App Store handoff language on the homepage and generated site artifacts

## Facts From The Repo

- The homepage already acknowledged the theme with copy such as `For the hardest cards and the happiest`.
- The default homepage demo starts on a sympathy example, which is one of the most tone-sensitive use cases.
- SEO/discovery breadth already exists in navigation, `/messages/`, `/blog/`, FAQ/schema, and generated message/blog surfaces.
- Repo copy already uses phrases like `blank-card anxiety`, `what to write`, and `that sound like you wrote them`, which support a high-stakes writing-positioning angle.
- The repo-visible product scope remains `iOS App Store` primary with `Android waitlist` secondary.

## Inferences

- Leading with emotionally difficult, high-stakes writing moments is a sharper homepage wedge than generic `any occasion` framing.
- The site does not need to give up broad occasion discovery to make that shift, because those discovery surfaces already exist and remain indexable.
- Hard-to-write positioning is most defensible when paired with truthful breadth language, not when pretending Prosepal is sympathy-only.

## Recommendation Adopted

Homepage default positioning sentence:

`Prosepal helps with the cards you do not want to get wrong first, while still covering everyday occasions across the site.`

Implementation decisions:

- Hero/default treatment now leads with hard-to-write cards.
- Supporting conversion copy keeps sympathy, apology, and encouragement in the lead set.
- Broad occasion coverage remains explicit in navigation, section copy, FAQ language, and generated discovery surfaces.

## App Store Alignment Review

- The repo does not contain editable live App Store listing copy.
- Repo-visible App Store handoff language was reviewed for consistency:
  - Website/App Store CTA still points to the same iOS listing.
  - Website positioning now emphasizes hard-to-write moments without changing the underlying product/category claim (`greeting card message generator` / card-writing help).
  - Platform scope remains aligned: iOS primary, Android waitlist secondary.

## Result

PASS: Homepage positioning now leads with hard-to-write moments while preserving broad occasion discovery and repo-visible App Store alignment.
